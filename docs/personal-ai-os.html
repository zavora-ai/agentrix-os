01Vision

The problem

People run their lives through a dozen disconnected tools: work email, Slack, two calendars, banking, health trackers, family chats, social media, news, music. Each has its own notifications and its own "assistant", and none knows what the others are doing. The person is the only integration layer, and the person is tired.

The shift

A chatbot answers questions. An operating system owns the context, schedules work across processes, and enforces permissions. The Personal AI OS applies those three ideas to a person's digital life. Suzy, the existing Agentrix coordinator persona, becomes the voice of a real orchestrator.

OS conceptPersonal AI OS equivalent
Kernel / schedulerMother Agent — routes, delegates, arbitrates, synthesizes
ProcessesSpecialized agents — one per life area, narrow tools
PartitionsWork World and Home World — isolated, reconciled by the kernel
TelemetryContent-free activity ledger feeding the intelligence layer
CapabilitiesObserve · Suggest · Automate, per agent, per tool effect
User's filesystemPersonal memory — known · assumed · recommended, user-editable

Design principles

1Orchestrate, don't chat. The Mother Agent coordinates; it does not do everything itself.
2Two worlds, one life. Work and Home stay separated by default; only the Mother Agent sees both.
3Inform and suggest, never control. Observations come with a question, not a verdict.
4Neutral language. "You've worked later than usual for two weeks", never "you're overworking".
5Never assume why. Report what changed; offer to help review.
6Least privilege everywhere. Discovery ≠ exposure. Agents get only the tools and memory they need.
7Human in control. Every external action has a permission level; one switch pauses everything.
8Honest data. No fabricated facts, no silent stubs.
9Memory is the user's. Readable, editable, deletable, exportable, with provenance.
10Health and money stay conservative. Wellness escalates to professionals; finance never moves money on its own.

03Mother Agent

The user's primary AI companion and operating-system-level coordinator. It orchestrates; it does not try to do everything itself.

1 · Intake
Classify

Domain(s), target agents, question vs action, urgency, or a clarifying question.

2 · Context
Assemble

Memory (known/assumed), today's baseline, open observations, session state. Facts, never raw inboxes.

3 · Delegate
Plan

Parallel or sequential tasks per world, each with a trace id, via the Work and Home mothers.

4 · Arbitrate
Reconcile

Boundary rules, conflicting proposals become one question, health/finance labels pass through.

5 · Synthesize
One voice

Suzy composes 2–4 sentences with actions, each tagged with its permission mode.

6 · Gate
Act

Observe → facts only · Suggest → pending approval · Automate → run, audit, undo.

What it is not. Not a chatbot answering from its own knowledge. Not omnipotent: it has no MCP tools of its own, only internal tools (get_context, delegate, read_memory, propose_memory, read_observations, compose). A bad routing decision means "wrong agent asked", never "wrong email sent". Not surveillance: it sees aggregates and observations, not every agent's raw content.

04Two primary worlds

The Mother Agent divides digital life into a Work World and a Home World. They stay logically separated, each with its own coordinating agent, identities and memory scope, and communicate only through the Mother Agent.

Work WorldWork Mother Agent · work_mother

Owns the work calendar, work identities (work email, Slack, GitHub, CRM, LinkedIn) and the work.* memory scope. Fans out to its sub-agents, merges results, returns one structured result.

Default posture: 💡 Suggest for anything that leaves the machine (send, post, schedule with others). ⚡ Automate allowed for internal organization (labels, task creation, summaries) once opted in.

🗓 Productivity✉️ Email💬 Team Communication📁 Project 🎯 Career📚 Research & Knowledge💼 Professional Social⚙️ Work Automation
Home WorldHome Mother Agent · home_mother

Owns the personal calendar, contacts, personal finance, health imports, media preferences and the home.* memory scope. Personal Google account is a separate identity from work.

Default posture: 👁 Observe for anything sensitive (health, money, social accounts). 💡 Suggest for reminders and plans. ⚡ Automate only for low-risk conveniences the user enables.

🏡 Family✅ Personal Productivity💪 Health & Wellness💸 Personal Finance 📻 AI Radio / Entertainment🎲 Social & Fun📱 Personal Social✈️ Travel & Errands
Example of separation and reconciliation. Mother → Work Mother → Email Agent runs while Mother → Home Mother → Family Agent runs. Neither sees the other's data. The Mother Agent sees both, and can say: "You have a family commitment tomorrow evening, but your current work schedule extends into that period. Would you like me to help reorganize your tasks?"

05Specialized agents

Every agent implements the same contract: an identity and world, one mission, an MCP tool allowlist with an effect class per tool, a permission mode, a memory scope, and typed outputs (card · observation · memory proposal · pending action). Filter by world, then click a card.

06Observation & intelligence layer

Sits above both worlds. Observes patterns without reading raw content, respects permissions, and produces observations the Mother Agent may surface. Deterministic statistics first; an LLM only to phrase the result in neutral language.

The activity ledger (foundation)

Everything the intelligence layer knows comes from one append-only, content-free table. Subjects are hashed; meta holds counts, categories and durations, never bodies. Domain is mandatory: that is what makes the Balance Agent possible.

activity_events
  user_id · ts · domain (work|home|shared) · agent_id
  kind   (intent | tool_call | card_resolve | approval | observation |
          task_postponed | reading | session_focus | notification …)
  effect (read | write_local | send_external | …)
  duration_ms · subject_hash (HMAC, no content) · meta (JSONB, schema-checked) · trace_id

Neutral language, enforced

DoDon't
"You've worked past 19:00 on 8 of the last 10 workdays; your usual is 17:30.""You're overworking."
"Three personal tasks have been moved four times.""You keep procrastinating."
"Would you like me to help you review what's changed?""You should stop working late."
State the number, the period, and the baseline.Guess the cause, attach a mood, or moralize.

A lint rejects banned vocabulary and requires number + period + baseline reference in every observation. Observations are deduplicated, cooled down (one per dimension per 7 days) and surfaced only in the briefing or on request, never as interrupting pop-ups.

Pattern Recognition

Working hours, reading habits, communication patterns, productivity, social media usage, sleep/routine, repeated tasks, frequently postponed tasks, changes in normal behaviour. Nightly plus 30-minute incremental.

Reading & Knowledge

What the user reads, how often, recurring topics, growing interests. Builds a personal knowledge graph: topic → item → project → person → career goal.

Balance

Compares Work and Home activity: attention share, spillover, boundary crossings, postponement debt, family cadence. Informs and suggests, never controls.

Digital Behaviour

Context switching, notification load, long uninterrupted work, repeated distractions, social consumption, unusual routine changes. Thresholds are the user's to tune.

Personal Baseline

Learns what is normal per dimension; flags meaningful deviation; asks, never assumes why. Detailed next.

07Personal baseline — "going off the book"

The system gradually learns what is normal for this user, then flags meaningful deviation. It does not assume why. It asks whether the user wants to review.

Learning model

Deviation|medianrecent − medianbaseline| > max(2.5 · MAD, floor); floors per dimension
Meaningful≥ 2 dimensions drifting, or 1 dimension for ≥ 10 days

ResetRe-learn after a life change: new job, baby, move

A self-awareness layer, not surveillance: the user sees exactly which dimensions are tracked, can switch any off, and can delete the ledger.

09Automation layer

The system takes authorized actions. Authorization is per agent, overridable per tool, and enforced where it matters: at the tool call. Every tool carries an effect class; the gate decides by effect, not by tool name, so new integrations slot in without new rules.

👁

Observe

Analyze, summarize, propose memory, emit observations. Cannot change anything outside the OS. read only.

💡

Suggest

Prepare an action and wait for approval. Drafts and artifacts (write_local) happen immediately; everything else becomes a pending action.

⚡

Automate

Perform predefined actions within approved recipes. Every run is audited and undoable where reversible. Never for public posts or money.

Where the gate lives

10Personal memory

Secure, user-controlled, transparent. The system always distinguishes what it knows, what it assumes, and what it recommends, and cites the kind whenever it uses a memory.

Known

The user said it, confirmed it, or it comes from an authorized source.

"You told me: no meetings before 10:00."
"From your calendar: Sara's birthday is 20 Oct."
EditForgetWhy?

Assumed

Inferred from patterns. Never becomes known without the user.

"I think you usually start work around 09:40 (based on 3 weeks of activity, confidence 0.8)."
ConfirmCorrectForgetWhy?

Recommended

A suggestion the system is currently making.

"I suggest protecting 18:00–21:00 on weekdays as personal time."

11Privacy & security

Privacy is a layer of the architecture, not a settings page. The existing codebase already has least-privilege tool allowlists, user-scoped artifacts, JWT auth, AWP trust gating and honest empty states. Phase 2 adds what a system holding a person's life requires.

🪪

Identity

Google OAuth + JWT today; add passkeys, device list and revoke, separate work/personal identities.

🔐

Encryption

TLS via Caddy today; add column encryption for sensitive memory, OAuth tokens, health and finance values; keys outside the DB.

🎛

Permission management

Modes + effect classes + recipes; trust center UI; per-world pause; one global switch.

🧩

Agent access control

Per-agent MCP allowlists (exists) plus memory scopes and ledger slices; the gate wrapper.

🧱

Data isolation

Domain scope on every row; cross-domain reads only via Mother/Balance API; no health or finance data reaches work agents.

🧾

Audit logs

Who (agent), what (tool, effect), on whose approval or recipe, when, undo state. User-visible viewer.

✍️

Consent

Persisted per category and world (calendar, email content, health, finance, social, location, reading) with purpose; storage refused without it.

⏳

Retention

Ledger 180 d raw · observations 365 d · audit 2 y · pending 30 d; nightly purge; export-then-delete account.

15Future expansion
